# Fidelity audit: app.js model mode vs analysis/predictive_process.py

Claim under audit (app.js:301-307): model mode "mirror[s] analysis/predictive_process.py: piecewise-linear inverse CDF over [log(tolerance), q05..q99] in log-dollar space, exponential tail in logs beyond q99, error dollars = |D| strictly above the year threshold."

Method: line-by-line comparison plus executable cross-checks — the app's model-mode functions copied verbatim into Node and run against `/Users/maxghenis/PolicyEngine/snap-qc-sim/app/public/model_data.json`, versus the repo's own Python machinery (`predictive_process.expected_error_dollars`, `_draw_log_magnitude`) on the same exported parameters, reconciled against the recorded pipeline numbers in `analysis/distributional_results.json`.

## Findings

**F1 — Interior inverse CDF (incl. u < .05 segment, flat segments): equivalent, proven bitwise. Severity: none.**
app/public/app.js:359-364 vs analysis/predictive_process.py:219-233. The JS `while (k < 8 && u >= nodeLevels[k+1])` computes exactly `searchsorted(levels, u, side="right")`; left node = `minLog` when k=0 (app.js:361) matches Python's `right_index == 0` branch (predictive_process.py:227-230); same expression tree for the interpolant. Verified on a 35,952-point grid (all 856 CO cases × 42 u values: exact boundaries 0.05…0.99, ±1e-12, segment midpoints, u=0, 1−2⁻³²): max |JS−Py| = 0.0, 31,672/31,672 interior evaluations bitwise equal. Flat segments (2,720 exported rows have ≥1 flat adjacent pair after 2-decimal rounding) act as point masses identically in both (fraction × 0).

**F2 — Tail branch and sign: equivalent. Severity: none (one info residual).**
app.js:356-358 (`u >= q99`; `+ tail·log((1−q99)/(1−u))`) vs predictive_process.py:219,236-243 (side="right" puts u = 0.99 exactly in the tail; `− scale·log((1−u)/(1−q99))`). Algebraically identical, boundary u = 0.99 yields exactly q99 in both, bitwise equal on the grid (including 1−2⁻³²). Residual: mulberry32 emits 32-bit uniforms, truncating the Pareto tail at |D| ≈ e^(q99+8.2) vs numpy's 53-bit; measured effect ≤ 0.005pp on state means (Node vs numpy at 200k draws). No fix needed.

**F3 — Monotonization: different operator, provably no-op on this export; latent divergence. Severity: low.**
predictive_process.py:116-125 floors then **sorts** (`np.sort(np.maximum(q, minLog))`); app.js:319-325 floors then applies a **running max**. These are not the same function: on [3,1,2,…] Python gives [1,2,2.5,…], JS gives [3,3,3,…] (confirmed numerically). They coincide only because exported vectors are already monotone: enforced at predict time (distributional_deviation_model.py:286-289), re-validated at export (scripts_build_model_data.py:153-156), and 2-decimal rounding (scripts_build_model_data.py:41-43) is monotone-preserving. Verified: max |JS−Py| = 0.0 across all 53 states; the JS floor binds on 0 entries (every exported q ≥ −0.69 > log 0.5 = −0.6931). Fix: assert monotonicity at load in app.js (throw if `st.q[i][k] < st.q[i][k−1]`) instead of silently repairing with a non-equivalent operator; add a comment naming the export invariant.

**F4 — Two different issuance totals in one model-mode render. Severity: medium (active defect for MN, DE).**
app.js:416 uses `MODEL.states[code].issuance` for `summarize()` (tiles t-expected, t-sd, t-delta), but app.js:437 passes `st.issuance` (data.json) to `tierBars`, whose per-segment "$/yr" labels and tooltips (app.js:175,186) therefore use a different dollar base for the same probabilities. Measured: MN 714,382,931 (model) vs 862,645,037 (data.json) — labels 20.8% above the tile; DE 0.44%; the other 51 states identical. Root cause: the model roster drops rows with missing STATUS/AMTERR/RAWBEN/BENFIX/HWGT (hurdle_deviation_model.py:185-193; MN loses 89 of 1,011 rows, DE 2), and the export sums w·iss over the truncated roster (scripts_build_model_data.py:174). The full-sample data.json total is the design-consistent annual-issuance estimate, so the MN tile understates expected cost ~17%. Fix: use one issuance in model mode — pass the same variable to both call sites, and prefer data.json's `st.issuance` for dollar conversion (the truncated-roster total estimates nothing policy-relevant); or export data.json's total into model_data.json.

**F5 — Observed-mode error gate is not the official definition (adjacent scope, affects cross-mode comparability). Severity: medium.**
snap_qc_sim/data.py:90-94 counts an error when STATUS∈{2,3} AND FSBEN present AND |RAWBEN − FSBEN| > 56 (amount = AMTERR). The official/pipeline definition is STATUS∈{2,3} AND AMTERR > 56 (hurdle_deviation_model.py:204-208,219). The repo's own docs warn the FSBEN difference misclassifies (hurdle_deviation_model.py:5-7; FINDINGS.md:86: |RAWBEN−BENFIX| = AMTERR for 99.997% weighted vs 83.6% for the FSBEN difference). Measured: CO observed sample point 7.3212% from data.json vs 7.4208% on the official-definition roster (distributional_results.json) — a −0.10pp composition error. The observed-mode mean is re-anchored to official so the level cancels, but which cases carry errors (spread, tier probabilities, lever hit shares) is distorted, and index.html:113 ("errors counted above the official $56 threshold") misdescribes the gate. Fix: gate on `amterr > threshold` in data.py:90-94 and rebuild data.json.

**F6 — Centering convention differs from the Python validation; app copy is essentially accurate. Severity: low (copy nit).**
app.js:375-384,408-415: shift = official − mean(4,000 base raw draws), same shift applied to scenario draws. Python validation (distributional_deviation_model.py:538-539): rate = official − observed_point + raw. Measured implications for CO on the exported params (20k draws): raw model mean 6.06%; app displays baseline mean = 9.97 exactly (by construction, MC-noise-free) with tier probs {10%: 0.55, 15%: 0.45}; the Python convention displays mean ≈ 8.72 (FINDINGS row 8.62 at its seed) with tier probs {5%: 0.19, 10%: 0.75, 15%: 0.06}. SD is identical under both (constant shift). Scenario deltas are shift-invariant in structure but evaluated at the official level in the app vs official-minus-gap in Python, which changes tier-crossing dollars. The app discloses this (app.js:306-307, app.js:393, index.html:118). Two nits: (a) index.html:118 says the raw-level gap "by state is documented there," but FINDINGS.md:160-165 tabulates only CO/CA/NY/TX plus national MAEs, not all 53; (b) the scenario mean inherits ±~0.03pp MC noise from re-estimating the mean at m = n+extra while the baseline is noise-free. Fix: soften "by state" to name the four validation states, or extend the FINDINGS table.

**F7 — Draw architecture: case bootstrap + process draw vs the validation's fixed roster. Severity: low (document it).**
app.js:348-372 resamples m = n+extra cases with replacement and redraws D per sampled case; distributional_deviation_model.py:498-540 holds the FY2024 roster fixed and redraws D only. The app therefore adds composition variance (and is what makes the extra-audits dial meaningful); its rate spread is not comparable to FINDINGS' "model SD" column. Measured CO rate-SD across 5 seeds × 20k draws: compound 0.86–0.95pp vs fixed-roster 0.80–0.89pp; note both are noisy because |D| has Pareto tail index α = 1/0.4674 ≈ 2.14 (single-run SDs at 4k–200k draws ranged 0.80–1.11pp — the FINDINGS 1.091pp CO figure is one 4k-draw realization). The displayed bill SD (t-sd) is over bounded tier dollars and is stable. The mode hint (app.js:393) describes the compound scheme accurately. Fix: one sentence in FINDINGS/docs noting the app's model mode compounds sampling and process variance, unlike the validation table's fixed-roster rows.

**F8 — Sign stage unused; p_pos is dead payload. Severity: info.**
app.js never reads `p_pos` (grep confirms). This loses nothing: `error_dollars` depends on |D| only, and Python's sign layer cancels exactly (predictive_process.py:283-284,287-299). p_pos is ~1/13 of the numeric payload (~0.2MB of 3.25MB). Fix: drop p_pos from the export or comment that it's reserved for signed displays.

**F9 — RNG stream differences: quantified, negligible. Severity: info.**
Index draw `(rng()*n)|0` (app.js:351): floor bias ≤ n/2³² ≈ 2×10⁻⁷ relative at n ≈ 1,000 (vs unbiased `rng.integers`); Bernoulli granularity 2⁻³²; conditional (JS) vs masked (Python, predictive_process.py:269-284) magnitude draws are distributionally identical. Cross-implementation agreement at 200k draws: means within ≤0.005pp on CO/CA/NY/TX/MN. One quirk: every state, both modes, base and scenario reuse seed 11 (app.js:49,338), so across-state table results share one uniform stream (Python uses distinct per-state seeds, distributional_deviation_model.py:566-572) — harmless for marginals, induces cross-state draw correlation. No fix required.

**F10 — Docs the app links to deny the integration exists. Severity: low.**
FINDINGS.md:171 ("does not yet implement … integration with the live simulator"; template at run_all.py:616) and docs/v2-error-model.md:12,32,108 ("the live simulator does not consume that export yet") predate commit 026a362 ("Add model-based simulation mode to the app (#9)"). index.html:118 links FINDINGS as the model mode's validation report while FINDINGS says the mode doesn't exist. Fix: update run_all.py:616 and the v2-error-model.md status row.

**F11 — Threshold convention: strictly greater in both; below-threshold quantile vectors can still cross via the tail in both. Severity: none.**
app.js:367 (`absD > thr`) vs predictive_process.py:299 (`magnitude > threshold`). For cases with q99 < log 56, interior draws contribute 0 and only u ≥ .99 tail draws can cross — identical logic in both (tail is unconditional). Exact threshold equality is unreachable with 2-decimal q (e^4.02 = 55.7, e^4.03 = 56.3). `conditional_survival`'s flat-segment strict-crossing care (predictive_process.py:135-140,178-180) is pipeline-only and has no app counterpart to diverge from.

**Numeric cross-check (task 8).** Analytic E[error dollars] via `expected_error_dollars` on the rounded export vs the pipeline's recorded exact integral on unrounded params, vs the app's verbatim code in Node (200k draws): CO 6.0590 / 6.0589 / 6.0617; CA 6.8256 / 6.8264 / 6.8342; NY 4.7698 / 4.7694 / 4.7735; TX 5.4734 / 5.4726 / 5.4759 (% rate). Export quantization moves state means ≤0.001pp (worst-case bound ±0.04pp via ±0.005 log shift); MC + ratio-estimator bias accounts for the remaining ≤0.008pp. The app's raw level reproduces the model to ~0.1% relative.

## Verdict

The specific claim at app.js:301-307 is **true at the level it is made**: the per-case conditional draw — nodes [log 0.5, q05..q99] with levels [0,.05,…,.99], the u < .05 join, flat-segment point masses, the u ≥ .99 exponential-in-logs tail, and the strict $56 crossing — is an exact implementation of predictive_process.py on the exported parameters (bitwise on the tested grid; ≤0.003pp on state means vs the exact integral). What the app does **not** mirror is the Python validation's state-level machinery, and it doesn't claim to: centering (official-anchored vs official − observed_point; disclosed, F6) and roster aggregation (case bootstrap vs fixed roster; described in the mode hint, F7). The real defects found are outside the draw path: the MN/DE dual-issuance render bug (F4), the observed-mode FSBEN error gate contradicting index.html's "official threshold" copy (F5), and stale integration-denial in the linked validation docs (F10). Nothing in the automated tests exercises the JS semantics; a durable fix for F1–F3 is a golden-vector CI test that runs a u-grid through Node and asserts equality against `_draw_log_magnitude` (the harness from this audit does exactly that: `/private/tmp/claude-501/-Users-maxghenis/51a1b6bb-c8a6-466b-bd9b-2620f722d19d/scratchpad/app_semantics.mjs` and `py_crosscheck.py`).
